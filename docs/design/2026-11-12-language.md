# Language setting (Dutch / English)

- Issue: #60
- Status: **approved** (2026-11-12)
- Date: 2026-11-12
- Builds on: [visual design](2026-11-09-visual-design.md), [costs](2026-11-09-costs.md) §7

## 1. Goal

Let the user choose the language of the app in Settings: System, Nederlands or English.
The app is Dutch only today: all texts live in `apps/web/src/i18n/nl.json` (i18next), and
dates and numbers are formatted with a fixed `nl-NL` locale in about twenty places.

## 2. Decisions

| Topic          | Decision                                                                                               |
| -------------- | ------------------------------------------------------------------------------------------------------ |
| Options        | System / Nederlands / English, same segment control as the theme                                       |
| Default        | System: Dutch when the device's first language is `nl*` (`nl`, `nl-NL`, `nl-BE`, …), English otherwise |
| Storage        | In the existing local settings (`p1meter.settings`), like the theme                                    |
| Switching      | Immediately, without a reload; "System" also follows a device language change (`languagechange` event) |
| Dates          | Month and day names follow the language; English uses `en-GB` (day–month order, 24-hour clock)         |
| Numbers        | Always Dutch format (`1.234,5 kWh`, `€ 3,10`), also in English                                         |
| Tariff terms   | Dutch terms that match the contract and annual statement stay Dutch in English (§6)                    |
| Not translated | PWA manifest name/description, `<title>`, splash screen, partner names, API-generated texts            |

## 3. Settings

`settings/storage.ts`:

```ts
export const LanguageSchema = z.enum(['system', 'nl', 'en']);
export type Language = z.infer<typeof LanguageSchema>;

const SettingsSchema = z.object({
  version: z.literal(1),
  ...
  language: LanguageSchema.catch('system'),
});
```

`.catch('system')` keeps stored settings without the field valid, so `version` stays 1.
`SettingsProvider` gets `setLanguage(language)`.

## 4. i18n

### 4.1 Resolving the language

`i18n/language.ts` (pure, tested):

```ts
export type AppLanguage = 'nl' | 'en';

/** The language to show: the explicit choice, or for "system" the device's first language. */
export function resolveLanguage(setting: Language, deviceLanguages: readonly string[]): AppLanguage;

/** Locale for date formatting: 'nl-NL' or 'en-GB'. */
export function dateLocale(language: AppLanguage): 'nl-NL' | 'en-GB';
```

Only the device's **first** language counts, so a Dutch phone with English as second
language gets Dutch, and a phone set to German gets English.

### 4.2 Startup and switching

- `i18n/index.ts` adds `en.json` to the resources and initialises with
  `resolveLanguage(loadSettings().language, navigator.languages)`, so the first render is
  already in the right language (no flash of Dutch).
- A `useLanguage(setting)` hook in `SettingsProvider` calls `i18n.changeLanguage()` and
  sets `<html lang>` when the setting changes and, for "system", on the window's
  `languagechange` event. It sits in the provider rather than in `Shell`, so every screen
  and test under the provider follows the setting.
- `fallbackLng` stays `nl`; a missing English text (should not happen, see §8) shows Dutch.
- `i18next.d.ts` keeps `nl.json` as the type source for keys.

### 4.3 Translations

`en.json` with the same keys as `nl.json`, including plural forms (`_one`/`_other`).
The English is plain, short UI English. Texts that are Dutch-specific (e.g. the energy tax
link to the Belastingdienst) stay factual about the Dutch situation, in English.

The hard-coded `week ${week}, ${year}` in `history/dates.ts` becomes a translation key
(`history.weekLabel`), so English shows "week 46, 2026" from the dictionary as well.

## 5. Dates

All `new Intl.DateTimeFormat('nl-NL', …)` instances (in `format.ts`, `history/dates.ts`,
`live/GasChart.tsx`, `live/RecentChart.tsx`, `pages/SettingsPage.tsx`,
`pages/TariffsPage.tsx`) move to one helper:

```ts
// i18n/dates.ts
/** Cached Intl.DateTimeFormat for the active language. */
export function dateFormat(options: Intl.DateTimeFormatOptions): Intl.DateTimeFormat;
```

The cache key is language + options; formatters are created once per language. The
`IonDatetime` in `HistoryPage` gets `locale={dateLocale(language)}`.

Number formatters (`Intl.NumberFormat('nl-NL')` in `format.ts`) stay as they are.

Re-rendering: components that format dates already use `useTranslation()` or get one, so
they re-render on `languageChanged`. Memoised chart data and labels include
`i18n.language` in their dependencies.

Examples:

| Where                 | Nederlands           | English              |
| --------------------- | -------------------- | -------------------- |
| History day heading   | `ma 9 nov 2026`      | `Mon, 9 Nov 2026`    |
| History month heading | `november 2026`      | `November 2026`      |
| Week axis label       | `ma` / `9 nov`       | `Mon` / `9 Nov`      |
| Last measurement      | `11 nov 2026, 09:37` | `11 Nov 2026, 09:37` |
| Energy                | `1.234,5 kWh`        | `1.234,5 kWh`        |

Note: `en-GB` puts a comma after the weekday ("Mon, 9 Nov 2026") and writes September as
"Sept" in short form; both are accepted.

## 6. Tariff terms that stay Dutch

In English the tariffs screen is translated, except these field labels, which keep the
Dutch term as it appears on the contract and annual statement. Their help text explains
the term in English.

| Key (`tariffs.fields.*`)             | Label in English UI                       | English help text (example)                           |
| ------------------------------------ | ----------------------------------------- | ----------------------------------------------------- |
| `energyTaxPerKwh` / `energyTaxPerM3` | Energiebelasting per kWh / m³ (excl. btw) | Energy tax; see the Belastingdienst or contract       |
| `compensationPerKwh`                 | Terugleververgoeding per kWh              | What you receive per kWh fed back to the grid         |
| `feePerKwh`                          | Terugleverkosten per kWh                  | Fee per kWh fed back; often 0                         |
| `supplierPerMonth`                   | Vastrecht leverancier per maand           | Fixed supplier charge, electricity and gas, incl. VAT |
| `gridPerMonth`                       | Netbeheerkosten per maand                 | Grid operator charge, electricity and gas, incl. VAT  |
| `taxReductionPerYear`                | Vermindering energiebelasting per jaar    | Energy tax reduction (heffingskorting), incl. VAT     |

Everything else on the tariffs screen is English, e.g. "Price per kWh", "Normal rate",
"Off-peak rate", "Single / Double / Dynamic", "VAT".

## 7. Settings screen

A new row in the "Weergave" (English: "Display") list, under Thema:

```
Taal                       (English UI: Language)
[ Systeem | Nederlands | English ]
```

The language names are always written in their own language (Nederlands, English);
"Systeem"/"System" follows the active language. The language segment has less padding
than the theme segment, so "NEDERLANDS" fits in Material style on a 390 px wide phone.

## 8. Testing

- `language.test.ts`: `resolveLanguage` for `nl`, `nl-BE`, `en-US`, `de-DE`, empty list,
  and the explicit choices; `dateLocale`.
- `i18n.test.ts`: every used key exists in `nl.json` **and** `en.json`; both files have
  exactly the same set of keys (no stale or missing English texts).
- `storage.test.ts`: settings without `language` load as `system`; an invalid value
  becomes `system`.
- `SettingsPage.test.tsx`: choosing English switches the settings screen to English and
  sets `<html lang="en">`; the choice is stored.
- `dates`/`format` tests run for both languages (day heading, week label, axis labels);
  numbers stay Dutch in English.

## 9. Out of scope

- The PWA manifest name and description, `<title>`, and the splash screen stay Dutch.
- Error texts generated by the API (the app already shows its own text per error code).
- Other languages.
