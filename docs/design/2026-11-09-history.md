- Builds on: [architecture](2026-11-09-architecture.md) §7.3–7.4, [visual design](2026-11-09-visual-design.md) §7.3,

## 1. Goal

Let a household look back: electricity and gas per day, week, month and year, with totals and
a comparison with the previous period.

## 2. Periods and buckets

All boundaries in local time (Europe/Amsterdam); weeks start on Monday (ISO).

| Period | Range                         | Bucket | Buckets                |
| ------ | ----------------------------- | ------ | ---------------------- |
| Day    | 00:00 – 24:00                 | hour   | 24 (23/25 on DST days) |
| Week   | Monday 00:00 – next Monday    | day    | 7                      |
| Month  | 1st 00:00 – 1st of next month | day    | 28–31                  |
| Year   | 1 Jan – 1 Jan                 | month  | 12                     |

The bucket start times are computed in TypeScript (DST-aware, like `localMidnight`) and are
the single source of truth; Flux returns the counter values, the API assigns them to buckets.

## 3. Data

Counters (`energy_consumed`, `energy_produced`, `gas_delivered`) with the household's corrected
orientation (#5). For each bucket: value = last counter value in the bucket − last counter value
in the previous bucket (the bucket before the period start serves as baseline).

```flux
from(bucket: B)
  |> range(start: <first bucket start − 1 bucket>, stop: <min(period end, now)>)
  |> filter(fn: (r) => r._measurement == "dsmr" and r.signature == SIG
                       and (r._field == IMPORT or r._field == EXPORT or r._field == "gas_delivered"))
  |> aggregateWindow(every: <1h | 1d | 1mo>, fn: last, createEmpty: false, timeSrc: "_start",
                     location: timezone.location(name: "Europe/Amsterdam"))
```

**Changed during implementation:** `aggregateWindow` over a whole year reads ~1.5 million points
and timed out. Instead the API looks up the **counter value at every bucket boundary** (one small
`range … |> last()` per boundary: 25 for a day, 13 for a year), with a lookback of 1 h (day),
6 h (week/month) or 3 days (year), plus a 400-day lookback for the baseline at the period start.
All periods answer in < 0.15 s. Hours missing just before a boundary are attributed to the next
bucket instead of turning the whole bucket into a gap.

Gap rules (shared with the gas chart; the gas chart's `hourlyGas` becomes a generic
`bucketDeltas(lastPerBucket, bucketStarts)`):

- bucket without a counter value → `null`;
- first bucket after empty ones → whole delta, `spansGap: true`, `gapStart`;
- negative delta → `null`;
- future buckets of the current period → `null` without gap marking.

## 4. Totals and comparison

- **Totals**: sum of the bucket values (import, export, net = import − export, gas). Because
  values after gaps carry the gap's use, the total is still correct as long as the counter has a
  value before and after the gap within the range.
- `complete: false` when the period contains empty buckets (in the past) or gap-spanning values
  that start before the period.
- **Comparison**: totals of the previous period of the same type. For the current period only
  the same elapsed part (e.g. Monday 00:00 – Wednesday 15:00 of last week). The client shows the
  change as a percentage per stream; "onvolledig" when either side is not complete; nothing when
  the previous value is 0 or missing.

## 5. API

`GET /api/v1/history?period=day|week|month|year&date=YYYY-MM-DD` (session required)

```ts
History = {
  period: 'day' | 'week' | 'month' | 'year';
  start: string; end: string;            // ISO, local period boundaries
  firstData: string;                     // ISO date of the household's first point (navigation limit)
  buckets: Array<{
    start: string;
    importKwh: number | null;
    exportKwh?: number | null;           // only with export
    netKwh?: number | null;              // only with export
    gasM3?: number | null;               // only with gas
    spansGap?: true; gapStart?: string;
  }>;
  totals: Totals;                        // { importKwh, exportKwh?, netKwh?, gasM3?, complete }
  previous: Totals | null;               // comparable part of the previous period
}
```

- `date` is any date in the period; invalid or future dates → `400 invalid_format`.
- Cache: completed periods 24 h, the current period 60 s.
- `firstData` is looked up once per household (30-day cache): `first()` over all time.

## 6. Web (History page)

```
┌─────────────────────────────┐
│ Historie                    │
├─────────────────────────────┤
│ [Dag][Week][Maand][Jaar]    │  segment
│  ‹   week 46, 2026   ›      │  tap the label → date picker
│ ┌──────┐┌──────┐┌──────┐┌──────┐
│ │Afname││Terug ││Netto ││Gas   │  totals + "▼ 12 % t.o.v. vorige week"
│ └──────┘└──────┘└──────┘└──────┘
│ Stroom (kWh)                │
│ ▆ ▅ ▃ ▂ ▃ ▅ ▇  —net line—   │  import up (navy), export down (green), net line
│ ▔ ▔ ▁ ▃ ▅ ▃ ▁               │
│ Gas (m³)                    │
│ ▂ ▃ ▅ ▆ ▄ ▂ ▁               │
└─────────────────────────────┘
```

- **Period state in the URL** (`/history?period=week&date=2026-11-09`), so back/forward and
  bookmarks work; default: Day, today.
- **Navigation**: ‹ › arrows (› disabled at the current period, ‹ at the period containing
  `firstData`); horizontal swipe on the charts (Ionic gesture, threshold 60 px) does the same;
  the label opens an `IonDatetime` (day: date, week: date → its week, month: month-year,
  year: year), limited to `firstData` … today.
- **Zoom in**: tapping a bar opens the period below (year → that month, month/week → that day).
- **Summary cards**: same style as "Vandaag"; comparison chip with arrow and percentage. Colour:
  less import or more export = green, more import = warning colour, |change| < 2 % = neutral.
- **Charts** use `useEChart` (one instance, #19): electricity bars (stacked around zero) plus a
  net line when the household exports; gas bars in a separate chart. Gap bars dimmed with a
  dashed outline; tooltip per bucket with values and "niet uitgesplitst, sinds …".
- Labels: Day `HH:00` (every 3rd), Week `ma 9`, Month `9`, Year `jan`.
- Loading skeletons; error with retry, as on Live.
